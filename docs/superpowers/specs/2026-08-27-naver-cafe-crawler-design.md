# 몽제 네이버 카페 크롤러 — 설계 (Design Spec)

- 작성일: 2026-08-27
- 상태: 설계 확정, 구현 계획(writing-plans) 대기
- 대상 카페 예시(유사 이벤트): `https://cafe.naver.com/f-e/cafes/30867744/menus/43`
  (실제 대상 게시판은 아직 미개설 — 개설 후 URL만 교체)

## 1. 목적

네이버 카페 내 지정 게시판의 게시글을, 운영자가 지정한 **기간(등록일 기준)** 으로
자동/수동 수집하여 **엑셀 파일**로 산출한다. 각 게시글 페이지에 진입해 **본문**까지
수집하고, 본문에 포함된 **이미지는 URL 수집 + 실제 파일 다운로드**까지 수행한다.
실패·오류는 운영자가 사후 확인할 수 있도록 로그와 에러 시트로 남긴다.

## 2. 확정된 요구사항

1. 지정 게시판의 게시글 목록을 자동 수집한다.
2. 각 게시글 페이지에 진입해 본문 데이터를 수집한다.
3. 수집 항목: **제목 / 본문 / 이미지 URL / 이미지 파일(다운로드) / 작성자명 / 등록일 /
   게시글ID / 게시글URL**.
4. 실행 방식: 운영자 **수동 실행**(기간 지정)이 기본. OS 스케줄러 등록으로 배치 실행 가능(문서 안내).
5. 산출물: **엑셀** 파일 1개(게시글 시트 + 에러 시트).
6. 크롤링 실패/오류를 확인할 수 있는 로그·리포트를 제공한다.

### 기간(등록일 필터)

- 운영자가 실행 시 **단일 기간**을 지정한다: `--from YYYY-MM-DD --to YYYY-MM-DD`.
- 포함 경계: 등록일이 **`시작일 00:00:00 ~ 종료일 23:59:59`** 안에 드는 글만 수집.
  - 예) `--from 2025-09-12 --to 2025-09-16` → 2025-09-12 00:00:00 ~ 2025-09-16 23:59:59.
- 등록일 기준(수정일 아님). 고정 8구간·"적립금 정확성" 로직은 **채택하지 않음**
  (초기 논의에서 열거됐으나 운영자 기간 입력 방식으로 단순화됨).

### 인증(로그인) — 현재 불필요

- 대상 게시판이 **비로그인 상태에서도 열람 가능**하다는 전제로, 로그인/세션 기능은
  **구현하지 않는다**.
- **향후 고려사항(구현 안 함):** 프로모션 시작 등으로 게시판이 회원 전용으로 바뀌면
  로그인 세션 확보 단계가 다시 필요해질 수 있다. 그때는 "실제 브라우저로 1회 수동
  로그인(캡차·2FA 직접 처리) → 쿠키(storage_state) 저장 → 재사용" 방식을 추가한다.
  `fetcher`가 세션 쿠키를 주입받을 수 있는 형태로 설계해 확장 여지를 남긴다.

## 3. 실행 환경 / 기술 스택

- 실행: **운영자 PC 로컬 실행**(Windows/Mac). 로그인 세션(향후)·엑셀·이미지·로그 모두 로컬.
- 언어: **Python 3.11+**
- 라이브러리:
  - 목록/본문 수집(A안): `httpx` — 카페 내부 JSON API 호출
  - 브라우저 폴백(B안): **Playwright**(Chromium) — 필요 시 벤더링된 `crawl4ai` 스킬로 래핑
  - HTML 파싱(본문·이미지 추출): `beautifulsoup4` + `lxml`
  - 이미지 다운로드: `httpx`
  - 엑셀 생성: `openpyxl`
  - 설정: `PyYAML`(`config.yaml`)
  - CLI: `argparse`(표준) 또는 `typer`
  - 테스트: `pytest`
  - 로깅: 표준 `logging`

## 4. 수집 전략 (A안 우선 / B안 폴백)

대상 `f-e` 카페 UI는 React SPA로, 목록·본문을 내부 JSON API(`apis.naver.com/cafe-web/...`)로
로드하는 것으로 알려져 있다. 단, **이는 미검증**이며 `selftest`에서 실제 응답으로 확정한다.

- **A안(권장): API 우선.** 내부 JSON API를 직접 호출해 구조화 데이터(제목·작성자·등록일·
  게시글ID)를 얻고, 본문 HTML에서 이미지 URL을 추출한다. 빠르고 레이아웃 변경에 강함.
- **B안(폴백): 브라우저 렌더링.** Playwright로 목록/본문 페이지를 렌더링해 DOM에서 추출.
  A안이 원하는 필드를 주지 못하면 자동 폴백한다.
- 판정은 **`selftest`**(첫 마일스톤)에서 수행: 비로그인으로 대상 게시판 1페이지·게시글 1건을
  받아 필드가 실제로 추출되는지, 이미지가 실제로 내려받아지는지 확인.

### 네트워크 주의

- 개발용 클라우드 환경은 egress 정책으로 `naver.com` 접근이 차단됨(403). 따라서 **실제
  네트워크 검증은 운영자 PC에서만** 가능하다. 저장소의 테스트는 네트워크 없이(픽스처 기반)
  동작해야 한다.
- 네이버 이미지 CDN은 적절한 **Referer 헤더가 없으면 403**을 반환할 수 있으므로, 이미지
  다운로드 시 게시글 URL을 Referer로 설정한다. 이 동작도 `selftest`에서 확인한다.

## 5. 컴포넌트 (단위 분리)

각 단위는 명확한 입출력을 갖고 독립적으로 테스트 가능해야 한다.

- **`fetcher`** — 입력: 게시판 URL, 기간(from/to). 출력: 게시글 레코드 리스트.
  - 목록을 최신순으로 순회하며 게시글 메타(ID·제목·작성자·등록일) 수집.
  - **조기 중단**: 등록일이 `from` 이전으로 넘어가면 이후 페이지 순회를 멈춘다(최신순 전제).
  - 기간 내 글만 본문 페이지 진입 → 본문 텍스트, 이미지 URL 목록 추출.
  - A안(httpx+API) 우선, 실패 시 B안(Playwright) 폴백. 세션 쿠키 주입 가능한 형태(향후 확장).
- **`image_downloader`** — 입력: 이미지 URL + 게시글ID + Referer. 출력: 저장된 로컬 경로.
  - `output/images/<게시글ID>/01.<ext>, 02.<ext> ...` 로 저장.
  - 이미지 단위 실패 격리(한 장 실패해도 나머지 계속) → 실패 목록 반환.
- **`filter`** — 입력: 레코드 리스트. 출력: 필터링된 리스트.
  - 등록일 경계(`from 00:00:00` ~ `to 23:59:59`) 적용.
  - **공지·상단 고정글 제외.**
  - **게시글ID 기준 중복 제거.**
- **`exporter`** — 입력: 필터링된 레코드 + 에러 목록. 출력: `.xlsx` 파일.
  - **게시글 시트** + **`_errors` 시트** 생성.
- **`cli`** — `run --from --to [--config path]`, `selftest`. 콘솔 요약 출력.
- **`selftest`** — 첫 마일스톤. 실제 게시판 1페이지·1글로 A/B안 판정 + 이미지 다운로드 확인.

## 6. 데이터 플로우

```
config.yaml (게시판 URL, 딜레이, 출력 경로)
        +
CLI: run --from D1 --to D2
        │
   fetcher: 목록 순회 (등록일 < from 이면 조기중단)
        │  → 기간 내 각 글 본문 진입
        │     {id, 제목, 작성자, 등록일, 본문, 이미지URL[]}
        ▼
   image_downloader: 각 이미지 다운로드 → 로컬 경로[]
        ▼
   filter: 경계필터 + 공지제외 + ID중복제거
        ▼
   exporter: monge_<from>_<to>.xlsx (게시글 시트 + _errors 시트)
        ▼
   콘솔 요약: 성공 N / 실패 M / 로그 경로
```

## 7. 데이터 모델 & 엑셀 스키마

### 게시글 레코드 필드

`게시글ID, 제목, 작성자명, 등록일(datetime), 본문(text), 이미지URL목록, 이미지로컬경로목록, 게시글URL`

### 게시글 시트 컬럼

| 번호 | 게시글ID | 제목 | 작성자 | 등록일 | 본문 | 이미지 URL | 이미지 로컬경로 | 게시글URL |
|---|---|---|---|---|---|---|---|---|

- 이미지 URL / 로컬경로가 여러 개면 셀 안에서 줄바꿈(또는 세미콜론)으로 구분.

### `_errors` 시트 컬럼

| 게시글ID | 게시글URL | 단계(list/article/image) | 사유 | 시각 |
|---|---|---|---|---|

## 8. 오류 처리 & 로깅 (요구사항 6)

- **로그 파일**: 실행마다 `logs/run_YYYYMMDD_HHMMSS.log` — 시작/종료, 페이지 진행,
  각 실패 글ID·이미지·사유.
- **실패 격리**: 글/이미지 단위 실패는 전체 중단이 아니라 스킵하고 계속.
  누적 실패는 `_errors` 시트로 집계.
- **세션 만료(향후 로그인 도입 시)**: 인증 실패 감지 시 재로그인 안내, 부분 결과 저장.
- **콘솔 요약**: 종료 시 "성공 N건 / 실패 M건 / 로그: 경로" 표시.

## 9. 설정 & 운영자 UX

- **`config.yaml`**: 게시판 URL, 목록 페이지 크기, 요청 간 딜레이(rate limit 예의), 출력 경로,
  (선택) 배치용 기본 기간.
- **명령 예시**:
  - `run --from 2025-09-12 --to 2025-09-16`
  - `selftest`
- **패키징**: 운영자용 실행 스크립트(Windows `.bat` / Mac `.command`) 더블클릭 실행 안내(README).
- **스케줄 배치**: Windows 작업 스케줄러 / cron 등록 방법을 README로 안내.

## 10. 테스트 전략 (TDD)

- **단위 테스트(네트워크 없이, 픽스처 기반)**:
  - `filter`: 경계값(시작 00:00:00 포함 / 종료 23:59:59 포함, 경계 바깥 배제), 공지·고정글 제외,
    게시글ID 중복 제거.
  - `exporter`: 시트 구성·필드 매핑, 다중 이미지 셀 표현, `_errors` 시트.
  - `fetcher` 파서: 저장해 둔 실제 API/HTML 응답 픽스처로 파싱 검증.
- **수동 통합 검증**: `selftest`를 운영자 PC에서 1회 — 실제 로그인 없이 수집·이미지 다운로드 확인.

## 12. 열린 항목 / 첫 마일스톤에서 확정할 것

- 내부 JSON API의 정확한 엔드포인트·파라미터(A안 성립 여부) — `selftest`에서 확정.
- 비로그인으로 목록/본문/이미지가 실제로 열리는지 — `selftest`에서 확정.
- 이미지 CDN Referer 요구 여부 — `selftest`에서 확정.
- 위 결과에 따라 A안/B안 확정 후 구현 계획(writing-plans)에 반영.
